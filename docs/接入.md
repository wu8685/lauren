# 接入

官方格式以这两页为准，本文不另造安装语法：

- Codex skills：<https://learn.chatgpt.com/docs/build-skills>
- Claude Code skills：<https://code.claude.com/docs/en/skills>
- Claude Code 插件清单：<https://code.claude.com/docs/en/plugins/manifest-reference>

Linux 上把 CLI 装进 `PATH` 的命令见 [../README.md](../README.md)。`go.mod` 要求 Go 1.22 或更新。没有已发布的二进制，也没有插件市场安装命令。

## 仓库里已经放好的入口

| 宿主 | 本仓库路径 |
| --- | --- |
| 共享正文 | `skills/lauren-workflow/SKILL.md` |
| Codex 仓库扫描 | `.agents/skills/lauren-workflow` |
| Claude Code 仓库扫描 | `.claude/skills/lauren-workflow` |
| 清单 | `.claude-plugin/plugin.json` |

两个宿主入口都是相对符号链接，指向 `../../skills/lauren-workflow`。解析发生在它们所在的项目里，不指回另一份 lauren 检出。清单里没有 hooks，也没有 MCP。v0.1 不把 hook 或 MCP 当作安全边界。替换二进制或 `skills check` 不会改宿主配置。

`lauren skills check` 只确认这些文件齐全，且 frontmatter 有 `name: lauren-workflow` 和 `description`。它不安装插件，也不注册 hook。查找顺序是：

1. 命令行给出的 `--root`
2. 没给 `--root` 时，可执行文件所在目录的上两级。`dist/lauren` 会指回构建它的检出；装到 `$HOME/.local/bin/lauren` 时，上两级是 `$HOME/.local`，那里通常没有 Skill
3. 当前工作目录

它不向上遍历目录，也不搜索 lauren 的安装位置或 git 克隆。没有全局安装器。二进制在 `PATH` 上时，要在目标项目根目录执行，或显式加上 `--root <项目根>`。

## 放到另一个目标项目

宿主按仓库扫描时，读的是目标项目里的 `.agents/skills` 和 `.claude/skills`，不是 lauren 的检出目录。在 lauren 仓库根目录执行下面的命令，把正文和两个入口放进目标项目。符号链接保持相对路径，在目标项目内解析。

```bash
TARGET=/path/to/other-project
mkdir -p "$TARGET/skills" "$TARGET/.agents/skills" "$TARGET/.claude/skills" "$TARGET/.claude-plugin"
cp -a skills/lauren-workflow "$TARGET/skills/"
cp -a .agents/skills/lauren-workflow "$TARGET/.agents/skills/"
cp -a .claude/skills/lauren-workflow "$TARGET/.claude/skills/"
cp -a .claude-plugin/plugin.json "$TARGET/.claude-plugin/"
```

`cp -a` 复制符号链接本身。复制后 `.agents/skills/lauren-workflow` 仍指向 `../../skills/lauren-workflow`，也就是 `$TARGET/skills/lauren-workflow`。然后在目标项目根目录检查：

```bash
cd "$TARGET"
lauren skills check
```

运行时状态在目标项目的 `.lauren/runtime/`，问题库在 `.lauren/problems/`。更新 CLI 时只替换二进制，不要用 `git reset` 覆盖这些项目数据。行为细节见 [v0.1.md](v0.1.md)。

## 启动钩子

依据 2026-11 的官方说明，不另造字段：

| 宿主 | 文档 | 配置 | 事件与输出 |
| --- | --- | --- | --- |
| Claude Code | [Hooks](https://code.claude.com/docs/en/hooks-guide) | `~/.claude/settings.json` | `SessionStart`。退出码 0 时，纯文本 stdout 进入会话 |
| Codex | [Hooks](https://learn.chatgpt.com/docs/hooks) | `~/.codex/hooks.json`。设置了 `CODEX_HOME` 时用 `$CODEX_HOME/hooks.json` | 同一个 `SessionStart`。纯文本 stdout 会作为额外开发者上下文。不写 `config.toml` 里的 hooks，避免两份一起加载 |

两边的钩子命令都是绝对路径的 `lauren host run --host <claude|codex> --home <家目录>`，并带 `timeout: 5`。stdout 就是 `session-context` 的人读文本，不是 CLI 的 JSON，也不使用 `additionalContext`。

冷启动用用户级配置，不把钩子放进会随工作区拷贝的项目文件。授权登记在 `~/.lauren/host-registry.json`，键是这个仓库的 git common dir。新建的链接工作区没有根 JSON、也没有项目里的 hook 文件时，只要还是同一个仓库，钩子仍会跑，并给出 `init-worktree`。别的仓库 stdout 为空，退出码 0，不注入这条项目的规则。

```bash
lauren --root /path/to/repo host install
lauren --root /path/to/repo host install --apply
lauren --root /path/to/repo host uninstall --apply
```

没有 `--apply` 只展示要改的路径和仓库范围。三次 `--apply` 只保留一份受管钩子，用户原来的权限和其他钩子还在。卸载只删 Lauren 的命令和这个仓库的登记。宿主配置不是合法 JSON，或目录不可写时，安装失败，原文件不动。

二进制不在 `PATH` 上时，钩子仍用安装时记下的绝对路径。上下文失败、不是这个仓库、或超过内部时限，钩子退出码是 0，stdout 为空，诊断在 stderr，避免把会话挂住。

这次没有启动 Claude Code 或 Codex 进程，也没有代写 Codex 的 hook trust。Codex 要在 `/hooks` 里信任这条非托管钩子之后才会真正运行。因此 `host_injected` 在 CI 里仍是 false：测试证明的是钩子命令的 stdout 与 `session-context` 一致，不是一个活的宿主会话。

## 为 macOS 交叉编译

在 Linux 或其他构建机上，于模块根目录按目标系统编译。不要把本机的 `dist/lauren` 拷到 macOS 上当可执行文件。

```bash
CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -o dist/lauren-darwin-arm64 ./cmd/lauren
CGO_ENABLED=0 GOOS=darwin GOARCH=amd64 go build -o dist/lauren-darwin-amd64 ./cmd/lauren
```

`arm64` 对应 Apple Silicon，`amd64` 对应 Intel。交叉编译只产出对应平台的二进制。本文不在 macOS 上安装，也没有在 macOS 上运行过 lauren。把文件拷到 macOS 之后如何放进 `PATH`，与 [../README.md](../README.md) 的 `install` 步骤相同，那一步尚未在 macOS 上实测。
