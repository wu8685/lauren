# lauren v0.1

这一版把讨论里的六阶段做成一个不用 LLM 的 CLI。讨论记录里的待讨论项没有因此永久冻结；下面只是 v0.1 的实现选择。

## 这一版做了什么

- `lauren init` 写 `lauren.project.json`，运行状态放在项目里的 `.lauren/runtime/`，与安装出来的程序分开。
- 一次只跟踪一个进行中的变更。ID 稳定，状态写在磁盘上，下次命令可以接着做。
- 阶段名称是：明确需求、制定方案、实现与自验、验收与交付、发布与观察、复盘与改进。
- 不发布时，验收之后进入复盘。发布时经过发布与观察。正常关闭只发生在复盘完成之后。
- 推进、回退、阻塞、恢复、取消由命令改变状态。没有把阶段改成任意值或把检查填成 pass 的命令。
- 检查命令来自项目配置的 argv，由 CLI 启动子进程。记录工作目录、命令、退出码、时间和脱敏日志。日志正文在证据文件里，状态 JSON 只留短预览。
- 证据绑定 git 根的 HEAD、未提交和未跟踪文件，以及配置内容和声明环境。这些变了，旧结果变为过期。运行目录自己不参与哈希。
- 不是 git 根，或项目目录不是 git 根时，检查记为 blocked，不能当成通过。
- 检查层次是 static、unit、integration、interaction、release-readback。低层 pass 不抬成高层 pass。退出码 75 记为 partial，不能通过必过门禁。静态要求可以由静态检查满足。
- 自验（`when: self`）和验收（`when: acceptance`）分开。`independent: true` 的要求不能由自验检查满足。
- 交付接受、发布声明、工具读回是三件事实。手填版本的来源是 declaration。`version=` 只从 release-readback 检查的输出读取。
- 问题有稳定 ID。没有处置去向不能正常关闭。`later` 不表示已修复。已验证修复要有同一检查的旧失败和当前候选上的新通过。
- 项目范围的问题不会改 Skill，也不会变成全局规则。
- Skill 在 `skills/lauren-workflow/SKILL.md`。Codex 仓库入口是 `.agents/skills/`，Claude Code 仓库入口是 `.claude/skills/`。`.claude-plugin/plugin.json` 只有名称和说明，没有 hooks 或 MCP。

## 这一版明确不做

- 不部署，不自动合并，不自动 `git pull` 或 `git reset`。
- 不发送通知。输出里没有「已通知」。
- 不认证人类，不防止有人直接改 `.lauren/runtime/state.json`。
- 不把换一个 agent 说成独立验收。
- 不做依赖图。相关证据一起过期。
- 不接真实发布平台。发布读回只跑配置里的命令。
- 同时只开一个变更。项目目录必须是自己的 git 根。
- 没有在 macOS 上跑过。远端验证是 Linux 上的测试、`go vet`、构建和示例脚本。

## 信任边界

`lauren.project.json` 里的 argv 会被执行。这是显式信任的项目配置，不是从变更目标拼出来的 shell。程序不上传数据，也不读取凭据文件。日志里形如 token 的赋值会被打码。

本地 CLI 的接受记录只表示「有人用这个命令写下了来源和理由」。仓库 CI 重跑，以及人自己是否接受，才是信任边界。
